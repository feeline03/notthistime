# Not This Time 增长 PM 数字人使用文档

## 它是什么

`not-this-time-growth-pm` 是 Not This Time / 我忍住啦 的 Codex 本地增长 PM 数字人。

它负责：

- 判断当前增长卡点。
- 制定每周增长实验。
- 给内容制作数字人下 brief。
- 给 ASO、付费页、埋点提出优化任务。
- 根据数据做复盘，决定继续、停止还是换方向。
- 读取项目里的 CSV 数据，让判断随着历史记录变强。

它的最终 KPI 是 app 收入增长，但第一阶段会先解决曝光、下载、激活、留存和付费漏斗里的最大卡点。

## 怎么调用

最直接的调用方式：

```text
使用 $not-this-time-growth-pm，帮我做本周 Not This Time 增长诊断。
```

如果你有数据，可以这样问：

```text
使用 $not-this-time-growth-pm，基于以下数据做本周增长诊断，并给我 3 个实验：

产品页浏览量：
下载：
国家/地区：
打开应用：
开始三分钟：
完成三分钟：
查看付费页：
点击购买：
购买成功：
本周内容发布数量：
内容表现：
用户评论/私信：
```

如果你已经把数据填进 CSV，可以直接这样问：

```text
使用 $not-this-time-growth-pm，读取 growth 目录里的 CSV，做本周增长诊断和下周实验计划。
```

如果你要它给内容数字人派任务：

```text
使用 $not-this-time-growth-pm，给内容制作数字人生成本周 brief。
目标是为 Not This Time 获取海外下载，平台优先 TikTok / Reels / Shorts。
```

如果你要它看 App Store 页面：

```text
使用 $not-this-time-growth-pm，评估这版 App Store 标题、副标题、关键词、截图和付费页，指出最大转化风险，并给出本周可改的优先级。
```

## 每周你需要准备什么

最小可用数据：

- App Store 产品页浏览量
- 下载量
- 国家/地区分布
- 本周发布了哪些内容
- 每条内容的大致播放/阅读/点赞/收藏/评论
- 评论区或私信里的真实用户反馈
- 是否有购买

埋点上线后，最好每周提供：

- 打开应用
- 开始三分钟
- 完成三分钟
- 查看付费页
- 点击购买
- 购买成功
- 收入

没有数据也可以用。它会告诉你现在缺哪些数据，以及应该先补什么。

## CSV 怎么填

日常不要维护 Markdown 表格，直接维护 `growth/` 里的 CSV。

`每周数据.csv`：每周填一行，记录 App Store 和产品漏斗。

`内容数据.csv`：每条内容填一行，记录平台、主题、Hook、播放、互动、评论和归因。

`用户反馈.csv`：每条评论、私信、评论区咨询、App Store 评论、用户访谈都可以填一行。重点保留用户原话。

`实验复盘.csv`：每个增长实验填一行。没有复盘的实验不算完成。

如果你想用飞书作为日常录入工具，按 `docs/feishu-growth-table-template.md` 建 4 张飞书表。每周复盘前，从飞书分别导出 CSV，然后覆盖 `growth/` 里的同名文件。

## 它会输出什么

默认输出 6 块：

1. 增长诊断
2. 当前漏斗数据
3. 本周 3 个增长实验
4. 给内容数字人的 brief
5. 建议更新到哪些 CSV
6. 需要补充的数据
7. 7 天后复盘什么

## 当前第一阶段建议

以你现在的数据看，第一阶段重点不是直接优化收入，而是：

- 拿到更多有效曝光。
- 验证哪个人群场景最有下载意愿。
- 尽快上线埋点。
- 用内容测试用户语言和痛点。
- 保持 App Store 页面不要跑题。

第一周建议让它重点做：

- 1 个内容渠道实验。
- 1 个 App Store 截图/定位实验。
- 1 个埋点/付费页观察实验。

## 和内容制作数字人的关系

增长 PM 数字人不直接“随便做内容”。它先判断增长目标，再给内容制作数字人 brief。

内容制作数字人应该接收这样的任务：

- 目标用户是谁。
- 用户在什么场景想吃。
- 这条内容测试哪个痛点。
- 平台和语言是什么。
- 要什么格式：短视频、图文、脚本、封面文案。
- 成功指标是什么。

后续可以单独创建第二个 skill：

`not-this-time-content-agent`

它专门根据增长 PM 的 brief 产出 TikTok、Reels、Shorts、小红书繁中、Reddit 等内容资产。

## 目前能力评分

当前版本约为 75 分。

它已经不是只会一次性回答的 60 分版本，因为现在有 CSV 数据表和历史复盘入口。只要你每周更新这些表，它会先读历史再判断。

它还没到 85 分，因为缺少 4 周以上的真实数据。

它还没到 90 分，因为目前还没有被验证过的稳定获客渠道、爆款内容角度、付费转化证据和留存数据。

提升方式：

- 连续 4 周更新 `每周数据.csv`。
- 每条内容都写入 `内容数据.csv`。
- 保留用户原话到 `用户反馈.csv`。
- 每个实验都在 `实验复盘.csv` 里写结论。
- 每次发现数字人判断错误，把错误原因写回 skill 或复盘表。

## 推荐固定节奏

每周一：

```text
使用 $not-this-time-growth-pm，基于上周数据做增长诊断，并制定本周 3 个实验。
```

每周三：

```text
使用 $not-this-time-growth-pm，检查本周实验执行到一半的数据，判断要不要调整内容方向。
```

每周日：

```text
使用 $not-this-time-growth-pm，复盘本周实验，判断下周继续、停止还是换角度。
```

## 注意事项

- 不要只让它生成内容，要让它先说明“为什么做这组内容”。
- 数据太少时，不要让它过早判断价格、付费页或商业模式失败。
- 涉及减肥、情绪性进食、暴食等场景时，避免医疗承诺和羞辱用户。
- 每次实验都要有成功标准，否则复盘会变成凭感觉。
