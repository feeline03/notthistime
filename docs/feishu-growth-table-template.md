# Not This Time 飞书增长数据表模板

## 建议结构

在飞书多维表格里建一个 Base，命名为：

`Not This Time 增长数据库`

里面建 4 张数据表：

1. `每周数据`
2. `内容数据`
3. `用户反馈`
4. `实验复盘`

字段名要和下面保持一致。每周复盘前，从飞书导出 CSV，并覆盖项目里的同名 CSV：

- `growth/每周数据.csv`
- `growth/内容数据.csv`
- `growth/用户反馈.csv`
- `growth/实验复盘.csv`

## 表 1：每周数据

用途：每周一行，记录 App Store 和产品漏斗。

| 字段名 | 建议类型 | 说明 |
|---|---|---|
| 周开始日期 | 日期 | 本周开始日期 |
| 周结束日期 | 日期 | 本周结束日期 |
| 版本号 | 文本 | App 版本或状态，例如 1.2.0 / 新版分发中 |
| 主要市场 | 多选/文本 | 美国、香港、澳大利亚等 |
| 产品页浏览量 | 数字 | App Store 产品页浏览 |
| 下载量 | 数字 | App Store 下载 |
| 产品页下载转化率 | 公式/百分比 | 下载量 / 产品页浏览量 |
| 打开应用 | 数字 | 埋点上线后填写 |
| 开始三分钟 | 数字 | 用户开始 3 分钟流程 |
| 完成三分钟 | 数字 | 用户完成 3 分钟流程 |
| 查看付费页 | 数字 | 看到付费页的人数 |
| 点击购买 | 数字 | 点击购买按钮的人数 |
| 购买成功 | 数字 | 成功支付人数 |
| 收入 | 数字 | 本周收入 |
| 退款 | 数字 | 本周退款 |
| 备注 | 长文本 | 异常、版本变化、渠道变化 |

建议视图：

- `周报视图`：按周结束日期倒序。
- `漏斗视图`：显示产品页浏览量、下载量、打开应用、开始三分钟、完成三分钟、查看付费页、购买成功。

## 表 2：内容数据

用途：每条内容一行，记录内容表现和用户反应。

| 字段名 | 建议类型 | 说明 |
|---|---|---|
| 发布日期 | 日期 | 内容发布时间 |
| 平台 | 单选 | TikTok / Reels / Shorts / 小红书 / 抖音 / Reddit / 其他 |
| 账号 | 文本 | 发布账号 |
| 语言 | 单选 | 英文 / 简体中文 / 繁体中文 / 粤语 / 其他 |
| 内容形式 | 单选 | 短视频 / 图文 / 帖子 / 评论回复 |
| 内容主题 | 文本 | 晚上破戒、情绪性进食、减脂期嘴馋等 |
| Hook | 长文本 | 开头第一句话或封面标题 |
| 链接 | URL | 内容链接 |
| 曝光或播放 | 数字 | 播放量/阅读量 |
| 点赞 | 数字 | 点赞数 |
| 评论 | 数字 | 评论数 |
| 收藏 | 数字 | 收藏数 |
| 转发 | 数字 | 转发数 |
| 主页访问 | 数字 | 如果平台提供 |
| AppStore点击 | 数字 | 如果可追踪 |
| 下载归因 | 数字/文本 | 能确认的下载或估计说明 |
| 用户原话 | 长文本 | 高价值评论原文 |
| 结论 | 长文本 | 这条内容学到了什么 |
| 下一步动作 | 长文本 | 复刻、改 Hook、停止、换平台等 |

建议视图：

- `本周内容`：筛选本周发布。
- `高互动内容`：按收藏、评论、转发倒序。
- `按主题分组`：按内容主题分组，看哪个痛点有信号。
- `待复盘`：筛选结论为空的内容。

## 表 3：用户反馈

用途：沉淀用户原话。这个表非常重要，后续标题、脚本、截图文案都应该从这里提炼。

| 字段名 | 建议类型 | 说明 |
|---|---|---|
| 日期 | 日期 | 反馈发生日期 |
| 来源 | 单选 | 评论区 / 私信 / App Store 评论 / 用户访谈 / 朋友试用 / 其他 |
| 国家地区 | 文本 | 美国、香港、台湾等 |
| 语言 | 单选 | 英文 / 简体中文 / 繁体中文 / 粤语 / 其他 |
| 用户原话 | 长文本 | 尽量原样复制，不要总结 |
| 反馈类型 | 单选 | 咨询 / 价格 / 功能 / 痛点 / 反对意见 / 表扬 / Bug |
| 关联场景 | 单选/文本 | 夜宵、压力、情绪、减脂期、暴食冲动等 |
| 用户意图 | 文本 | 想下载、想了解价格、觉得被说中、担心没用等 |
| 是否影响产品 | 单选 | 是 / 否 / 待判断 |
| 是否影响内容 | 单选 | 是 / 否 / 待判断 |
| 处理结论 | 长文本 | 怎么理解这条反馈 |
| 下一步动作 | 长文本 | 改文案、做内容、改功能、暂不处理 |

建议视图：

- `用户原话库`：显示用户原话、关联场景、用户意图。
- `内容素材`：筛选是否影响内容 = 是。
- `产品需求`：筛选是否影响产品 = 是。
- `价格/付费异议`：筛选反馈类型 = 价格。

## 表 4：实验复盘

用途：每个增长实验一行。没有复盘的实验不算完成。

| 字段名 | 建议类型 | 说明 |
|---|---|---|
| 实验ID | 文本 | 例如 EXP-001 |
| 开始日期 | 日期 | 实验开始 |
| 结束日期 | 日期 | 实验结束 |
| 实验类型 | 单选 | 内容测试 / ASO / 截图 / 付费页 / 埋点 / 产品激活 / 其他 |
| 目标 | 长文本 | 这个实验要解决什么问题 |
| 假设 | 长文本 | 如果做 X，就会因为 Y 带来 Z |
| 动作 | 长文本 | 实际做了什么 |
| 渠道或页面 | 文本 | TikTok / App Store / 付费页等 |
| 素材或版本 | 文本 | 对应内容、截图版本、文案版本 |
| 成功指标 | 文本 | 播放、下载、完成三分钟、购买等 |
| 最低样本 | 文本 | 至少多少播放/页面浏览/下载再判断 |
| 结果数据 | 长文本 | 实际结果 |
| 结论 | 长文本 | 成功/失败/无结论，为什么 |
| 决策 | 单选 | 继续 / 停止 / 修改后继续 / 等更多数据 |
| 学到什么 | 长文本 | 沉淀为以后要遵守的经验 |
| 下一步动作 | 长文本 | 下一轮怎么做 |

建议视图：

- `进行中实验`：筛选结束日期为空。
- `待复盘`：筛选结果数据或结论为空。
- `成功实验`：筛选决策 = 继续。
- `失败经验`：筛选决策 = 停止。

## 每周使用流程

每周一：

1. 在飞书更新上周 `每周数据`。
2. 补齐上周发布的 `内容数据`。
3. 把有价值评论复制到 `用户反馈`。
4. 把已结束实验写入 `实验复盘`。
5. 分别导出 4 张表为 CSV。
6. 覆盖项目里的 `growth/` 同名 CSV。
7. 在 Codex 里调用：

```text
使用 $not-this-time-growth-pm，读取 growth 目录里的 CSV，做本周增长诊断和下周实验计划。
```

## 导出注意事项

- 导出时保留第一行字段名。
- 不要改字段名，否则 Codex 可能识别错。
- 如果飞书导出的文件名带括号或日期，手动改回固定文件名。
- 空字段可以保留为空，不要填 `-` 或 `无`，除非这本身是有意义的信息。
- 用户原话尽量保留原文，不要翻译成自己的总结。
