# Not This Time Growth Framework

## Funnel

Use this funnel for all diagnosis:

Exposure -> App Store product page view -> Download -> First open -> Timer start -> Timer complete -> Paywall view -> Purchase tap -> Purchase success -> Repeat use

- 重复使用

## Stage Rules

### Exposure Bottleneck

Signals:

- Product page views are low.
- Content has low reach.
- Download conversion may look high, but sample is too small.

Default response:

- Do not obsess over paywall yet.
- Run channel and positioning tests.
- Improve repeatable content production.
- Keep ASO clear enough to avoid wasting traffic.

### Store Conversion Bottleneck

Signals:

- Product page views are meaningful, but downloads are weak.
- Screenshots do not explain the craving moment.
- Title/subtitle/keywords mismatch user search language.

Default response:

- Test first screenshot, subtitle, and first three screenshot claims.
- Remove off-topic or generic claims.
- Use user-problem language before feature language.

### Activation Bottleneck

Signals:

- Downloads happen, but 开始三分钟 or 完成三分钟 is weak.
- Users do not understand what to do in the first session.

Default response:

- Make the first action obvious.
- Reduce setup before the first 3-minute pause.
- Track first-session completion.

### Retention Bottleneck

Signals:

- Users complete one timer but do not return.
- The app is useful only when remembered during cravings.

Default response:

- Test reminders, widgets, lock-screen entry points, post-timer reinforcement, and "next craving plan".
- Create content that teaches when to open the app.

### Paywall Bottleneck

Signals:

- Activated users see paywall but do not purchase.
- Purchase taps are low.
- Price objection appears in feedback.

Default response:

- Test offer clarity before changing price.
- Compare lifetime unlock against subscription only after enough paywall views.
- Make paid value concrete: unlimited uses, voice guidance, custom timers, quick access during cravings.

## Minimum Useful Samples

Use these as rough thresholds, not hard laws:

- Store conversion: 300+ product page views.
- Activation: 100+ downloads.
- Paywall: 100+ paywall views.
- Purchase rate: 300+ paywall views or clear qualitative evidence.
- Content angle: 10+ posts per angle before rejecting the angle.

## Capability Score

Use this score when the user asks how strong the digital employee is:

- 60/100: has diagnosis framework and output templates, but no accumulated data.
- 75/100: reads weekly CSVs and uses experiment history before making plans.
- 85/100: has 4+ weeks of clean funnel, content, user feedback, and experiment data.
- 90/100: can identify repeatable winning channels, content angles, and product/paywall changes from historical evidence.

The skill should not claim autonomous self-improvement. It improves when the project CSVs are updated and when its rules are revised after real failures or wins.
